- Write a C program that prints TAP through `codecoremorph_tap.h`, which CodeCoreMorph writes beside the test: `#include "codecoremorph_tap.h"` first, then the project's headers the way its own tests include them (see the example below).
- Each test case is a `static void name(void)` function of checks: `CCM_CHECK(condition)`, `CCM_CHECK_INT(got, expected)` for integers (compared as `long`), `CCM_CHECK_UINT(got, expected)` for unsigned values and sizes, `CCM_CHECK_STR(got, expected)` for C strings (NULL allowed), `CCM_CHECK_NEAR(got, expected, within)` for floating point. A failing check prints the values it compared.
- `main` runs each case with `CCM_RUN(name);` and ends with `return ccm_done();`. A case is a test named after its function, so name the functions after what they check, in snake case and unique in the file (for example `htab_add_counts_a_word_twice`). Write nothing else to standard output.
- The test program is linked with the library that builds the code under test. Free what the code allocates, as its callers do, and make everything but `main` static.
- The project compiles as ${source}, with its own warning flags: write ${source} C. Before C99 that means `/* */` comments only, declarations at the start of a block, and no `snprintf`, `long long`, `inline`, `bool` or mixed declarations.
