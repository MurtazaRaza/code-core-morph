# Porting C++ to Rust

CodeCoreMorph can replace the C++ code behind a C header with a Rust crate, one header at a
time. The header and the project's C++ tests stay exactly as they are: the tests call the Rust
code through the header, so they decide whether the port is right, and CodeCoreMorph checks
that the crate exports the header's C interface with the same signatures.

This first step suits code that already sits behind a C interface (functions declared
`extern "C"`). Porting whole C++ projects, classes and templates included, comes in later
phases.

## What you need

- A CMake project whose tests build and pass, as for any migration.
- The Rust toolchain. Natively: `codecoremorph toolchain install rust` (it installs the C++
  toolchain too, since a port builds both). In Docker: build the image once with
  `scripts/build-image rust` (`.bat` on Windows).

## The manifest

```yaml
version: "1.0"
project:
  name: textkit
  source_dirs: [src, include]
  test_dirs: [tests]
migration:
  source: {language: cpp, standard: cpp17, build_system: cmake}
  target: {language: rust, standard: rust2021, rules: [port_c_abi_module]}
```

The target's standard is a Rust edition (`rust2015` to `rust2024`). A port has no standard bump,
and takes port rules only; `codecoremorph validate` checks each side against its own adapter.

## What a unit does

`codecoremorph plan` makes one unit per C header whose functions the project's C++ sources
define. For `include/textkit/ring.h`, defined in `src/ring.cpp`, the unit holds `src/ring.cpp`,
the header (read-only) and the CMake files. Then:

1. The `rust-crate` codemod creates `rust/textkit_ring/` (a `staticlib` with `Cargo.toml`,
   `Cargo.lock` and an empty `src/lib.rs`) and adds a marked block at the end of the top-level
   `CMakeLists.txt` that builds it with [Corrosion](https://github.com/corrosion-rs/corrosion)
   and links it to the library that compiled the module.
2. The agent writes the Rust implementation of every function the header declares
   (`#[no_mangle] pub extern "C" fn ...`), deletes the C++ sources and takes them out of CMake.
3. CodeCoreMorph builds the project with CMake (Corrosion builds the crate), runs the C++ tests,
   and compares the header with the C header the crate really exports (generated by cbindgen).
   Cargo's own error messages go back to the agent when the build fails.

The unit may create files under `rust/` and edit the unit's C++ and CMake files; it may not
edit the header or the tests. Builds run offline and `--locked`; a crate's dependencies are
fetched first, with the network on for that step only. Build scripts (`build.rs`), build
dependencies and procedural macros are refused, like any new command that runs at build time.

## With Claude Code

The `codecoremorph` skill knows about ports: ask Claude Code to "port the ring buffer behind
`ring.h` to Rust", and it runs the plan's units as for any migration. See
[Migrating with Claude Code](claude-code.md).
